# 串流设置导航与生效时机

## 已确认设计

用户要求在首页导航栏增加设置图标，点击后 push 到现有 `SettingsViewController`，允许在串流前配置连接参数。此要求取代此前首页不提供设置能力的约定。串流内继续通过浮动按钮打开现有侧栏，复用同一设置 VC 和全局持久化。

首页使用左侧齿轮按钮，保留右侧主机选择入口。设置页标题为“串流设置”，通过系统返回按钮退出，不显示侧栏功能菜单或重复关闭按钮。内容不延伸到导航栏下方，也不保留旧抽屉的 overdraw 宽度。未选主机时仍能保存全局设置；选定配对主机时查询该主机的目标能力，查询不会启动串流。

## 生效规则

以下分类描述当前客户端实现，不代表协议理论上能支持的动态能力。所有选项自动保存，串流侧栏逐项展示生效说明，首页也能看到相同分类。

| 设置 | 当前生效时机 | 实现依据 |
| --- | --- | --- |
| 串流统计 | 当前串流立即生效 | 创建或取消统计定时器 |
| 屏幕控制器 | 当前串流立即生效 | 更新控制等级及自动模式观察；触摸屏模式下不可用 |
| 串流目标 | 结束当前串流后重新连接 | 通过 launch/resume 的 sidelantern_mode 提交 |
| 分辨率、帧率、码率 | 结束当前串流后重新连接 | 创建 StreamConfiguration 和 C 连接参数时读取 |
| 优先编码格式、HDR | 结束当前串流后重新连接 | 连接时协商视频格式与 HDR |
| 画面帧节奏 | 结束当前串流后重新连接 | 初始化 VideoDecoderRenderer 时读取，当前无动态 setter |
| 触控模式 | 结束当前串流后重新连接 | 创建触控处理器和缩放容器时读取 |
| 多手柄模式、交换 A/B 和 X/Y | 结束当前串流后重新连接 | 初始化 ControllerSupport 的配置与按钮处理 |
| 在主机播放声音 | 结束当前串流后重新连接 | launch/resume 的音频参数 |
| Citrix X1 鼠标支持 | 结束当前串流后重新连接 | StreamView 初始化时启动专用鼠标服务 |
| 优化游戏设置 | 下次启动游戏时由主机决定 | launch/resume 的 sops 参数；重连不保证重启或修改运行中的游戏，Sunshine/SideLantern 不保证支持 |

串流内更改触控模式属于下次连接配置，不能立即据此改变当前屏幕控制器的可用性。当前控制器应依据本次串流实际触控模式，避免仅保存新模式就导致部分即时变化。

## 生命周期和保存

push、侧栏嵌入使用同一设置布局，离开 push 页面时保存，普通选择即时保存。主机传入不强制提前加载尚未挂载的页面；屏幕尺寸与刷新率优先取当前 scene window。自定义分辨率编辑过程中不保存未确认或零尺寸值，确认后保存并刷新显示，取消时恢复原选择。

## 验证范围

构建 iOS Debug 模拟器、签名 Release 与受影响的 tvOS 共享代码；检查导航 push/pop、导航栏避让、无主机下编辑和持久化、设置生效说明，以及串流侧栏继续正常展示。更新已授权的 iPan 并验证启动。Windows 串流和按钮拖动由用户验证，本次不进行这些测试。
