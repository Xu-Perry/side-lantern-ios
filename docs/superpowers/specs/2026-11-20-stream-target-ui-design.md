# 串流目标设置界面

## 已确认范围

在 iPhone/iPad 现有设置页增加“串流目标”，三个互斥选项如下：

| 目标 | 预期服务端行为 |
| --- | --- |
| 只连主屏幕（默认） | 串流主屏幕。 |
| 只连副屏幕 | 串流副屏幕，同时熄灭主屏幕。熄屏是此模式的固定行为。 |
| 无线副屏 | 将客户端作为电脑的无线扩展屏，主屏幕保持正常使用。 |

本阶段实现界面、本机保存与服务端接口接入。主机未选定时提示选择已配对主机；选定后显示目标可用状态及失败原因，不将预期行为显示为实际连接状态。

## 界面

新增区域位于分辨率设置之前。采用三个纵向单选卡片，包含图标、名称、说明和选中标记，沿用设置页的深色背景和紫色强调色。整个卡片可点击，支持 VoiceOver 激活、选中状态和动态字体。设置位于串流中的功能侧栏，首页导航栏也可 push 同一设置 VC，在串流前配置；共用一套 UIKit 组件，按实际可用宽度换行。横屏不缩放主区域；Duo 竖屏按折痕分区。详见 [串流工作区设计](2026-11-20-stream-workspace-design.md) 和 [设置导航与生效时机](2026-11-20-settings-navigation-design.md)。

设置页使用滚动视图与纵向约束布局，安全区域由约束处理。分辨率等较多选项以及大字体下无法完整显示的选项使用原生菜单；简单选项保留分段控件。`SettingsChoiceView` 继续使用原分段控件作为值和事件来源。设置变更和关闭时保存设置；目标偏好仍即时保存。主机页隐藏无用的返回按钮，标题和主机内容在可用区域内布局。

选中项立即写入本机偏好，关闭设置、终止应用或重新打开后恢复。初次使用、未知或损坏的保存值回到主屏幕。设置沿用现有页面的全局作用域。

## 模块与数据

- `StreamTargetPreferences`：定义客户端内部的三个目标值，负责读取、验证和保存独立的应用偏好，不修改现有 Core Data 模型。
- `StreamTargetSettingsView`：只负责展示和选择，选择变化通过 `UIControlEventValueChanged` 通知设置控制器。
- `SettingsViewController`：加载偏好、处理保存，通过滚动约束布局显示目标与原有设置，并管理原生设置页的关闭。
- 新增文案提供简体中文与英文资源，其他语言按应用默认英文回退。

三个保存值只用于客户端本机偏好，由协议映射分别转换为 `primary`、`secondary`、`extend`。服务端接口参照提交 `4f718ba9eb5784c17bb07e35a755df0a4095ec21`。

## 接口接入

- 使用现有 `HttpManager` 的 GameStream HTTPS 端口、配对客户端证书和服务端证书校验，查询 `GET /sidelantern/v1/stream-modes`。
- `StreamModesResponse` 解析 XML 根节点的 `status_code`、`version=1` 及三个 `mode` 节点的 `id`、`available`、`reason`。无效、重复或缺失节点及未知协议版本不能视为能力确认。
- 打开串流设置时，使用当前会话的已配对主机异步查询；忽略已被后续查询替代的结果。查询和选择不会启动串流或改变 Windows 显示状态。
- 串流启动前重新查询，检查所选模式当前可用。随后在现有 `/launch` 或 `/resume` 中追加 `sidelantern_mode`。失败时展示稳定原因代码对应的中英文说明，不切换为其他目标或自动结束已有会话。
- `404`/`501` 表示主机没有提供此接口。只有默认主屏选项可沿用原 GameStream 配置，并在设置中说明来源仍由主机控制。副屏及扩展模式不静默回退；认证失败、网络错误及无效 XML 不作为旧主机兼容条件。
- 无线副屏对应服务端 `extend`，需要用户事先在 Windows 配置扩展显示器并在 SideLantern 指定来源。`secondary` 要求恰好两块活动显示器，临时停用主屏后的布局恢复由服务端管理。

tvOS 不增加选择入口，本阶段只验证共享项目仍可构建。

## 验证

1. 检查默认主屏幕、三个选项互斥、点击后保存、重新加载恢复，以及未知偏好的回退。
2. 用户后续要求运行界面验证，已使用 iPhone 15 Pro Max 与 iPad mini 模拟器检查全屏设置、居中面板、滚动、较大字体和原生菜单；Windows 串流联调仍留待回家后进行。
3. 检查中英文文案及“暂未生效”提示。
4. 构建 iOS Debug/Release，并验证 tvOS 编译兼容性。
5. 使用协议检查程序验证偏好恢复、字段映射、能力 XML、无效响应、旧主机兼容分类和启动拒绝原因。按用户要求，本轮不连接 Windows 主机、不进行显示器切换或熄屏实测。
